## whoami

I'm a chef who cooks, but not in the kitchen. I solve problems for a living using 1s and 0s.

Mostly mobile. I've been shipping iOS and Android apps with React Native and Flutter since 2022, and I go into web and backend whenever the product needs it. My day job is React Native on [Stadioss](https://stadioss.com). I work remotely from Pakistan with their team in France. I also take freelance projects, and in the evenings I work on a few products of my own.

## If you're hiring me for a project

- **A mobile app, from Figma to the store listing.** React Native (Expo) or Flutter, one codebase for iOS and Android.
- **Moving from Flutter to React Native, or fixing a slow app.** I've done it on a live product (BitcyClub). Janky lists and dropped frames are my favourite kind of bug.
- **Integrations.** REST APIs, Firebase, Supabase, Stripe, maps, push notifications, AR try-on.
- **The web side.** Next.js or Remix sites, and admin panels for the app you already have.
- **Fast pages and sites.** Slow sites lose people. I go through it like a checklist: measure first, then fix images, caching, bundle size and render paths. Static assets go on S3 behind Cloudflare. I don't call it done until Lighthouse and Core Web Vitals agree.
- **Getting it to production and keeping it there.** CI/CD pipelines that test and build on every push, deploys to AWS, Vercel or Cloudflare, and app builds through EAS. Releases become boring, which is the goal.
- **Performance work on what you already have.** Profiling slow screens, heavy re-renders, long lists and cold starts, on mobile and web.

How it usually goes: we agree on the problem and what "done" means, I break it into weekly milestones you can actually check, tests run in the pipeline before anything ships, and after launch I handle store submission, release notes and the fixes. I don't disappear on release day.
